Here’s the engine for one message. Step one: Muse Spark picks the few cards this request needs, which ones are key, and how high the stakes are. One call over a bounded index, about 150 tokens of memory instead of years of history. Step two is plain code, the don’t-nag rule: it only asks when a key card is a guess, the stakes are real, and nothing was asked in this chat. Usually the answer is no. Step three: the answer, right away. If it’s a booking or an order, Muse Spark calls a draft tool, so you get a real draft built from your memory, and the check line rides above it. Step four is you: tap still true, tap not anymore, or just keep chatting, which counts as a quiet yes. Step five happens after the answer: one model writes new cards, code rules and a second model, Muse Wonder, check them, and only then do they enter your memory. Every step is visible under the info button, and any agent can use the same layer over three HTTP calls.
